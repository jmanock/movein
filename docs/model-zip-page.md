# Model ZIP utility page

ZIP pages are address-research starting points, not provider guarantees. The shared `LookupResults` component supplies the model; the underlying jurisdiction and provider records make each page local.

## Required model

- Canonical title, description, breadcrumb, FAQ schema, and indexability based on the coverage gate.
- Mailing city, county, jurisdiction status, location-review date, and a local moving overview.
- A prominent warning that ZIP codes cross municipal, utility, building, and network boundaries.
- Electricity, water/sewer, Internet, trash/recycling, and local-government sections with official sources and reviewed dates.
- Multiple possible Internet providers where verified relationship data supports them; neutral alphabetical order; exact-address confirmation and official availability links.
- Clear next steps for utility setup, Internet transfer, address changes, homeowner/renter guidance, emergency contacts, and My Move.
- No natural-gas assumption, price promise, affiliate ranking, or duplicated location template claims.

## 32757 benchmark

Mount Dora / Lake County is the early clicked-page benchmark. Its records must preserve the difference between the USPS mailing city and the property’s actual jurisdiction. City of Mount Dora electricity, water/sewer, trash, or government resources are possibilities only where the stored evidence supports them; every property still requires confirmation. Internet records remain address-check-required.

## 32720 comparison

DeLand / Volusia County uses the same interaction and evidence structure but different local records. Its electric, city utility, waste, and jurisdiction context must come from its own verified dataset relationships. Copy and links should never be cloned from 32757 merely because both pages share the component.

## QA

For each benchmark, test metadata and canonical output, indexability, heading hierarchy, official links, provider dates, address qualifiers, mobile overflow, browser-local actions, and related links. A ZIP page fails the model if it implies whole-ZIP service or if a generic provider card could pass without a provider name, technology/type, and official address checker.
